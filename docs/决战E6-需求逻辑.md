0.1 全局路线与机制
路线固定：ADVANCE_CHOICE 永远走最上方（ADVANCE_CARD_POSITIONS[0]，收益最大化）。无分支图，无需卡面 OCR。

节点推进：地图只走一条直线（A→B→…→J），保留 chr(ord(node) + 1) 的字母硬加逻辑。遇到未知节点 U 保持 U，不得推进。

结算页极速跳过：完全废弃战果采集（关闭 collect_result_info）和评级识别。战斗结束后，无需等待任何结算动画，绝不读血量，直接疯狂连点屏幕，直到检测到回到地图界面（出现编队/出征按钮）即可。

SL 死锁破局（6-1首次进图）：若在 6-1 首次进图弹出购买页时杀进程重进，依然停留在购买页且背包为空、无“关闭”按钮。此时直接点击最左侧第一张卡（必为考文垂）并点黄色“确定”即可破局。

0.2 阵型与夜战规则
全局默认：一律使用复纵阵。

特定节点：仅在 E6-1(B,G,J)、E6-2(C,H,J)、E6-3(D,G,J) 这 9 个夜战关键点，使用梯形阵。

判定依据：复用现有 DecisiveLogic.is_key_point()（与 _KEY_POINTS[6] 完全重合），废弃依赖 enemy_spec.yaml 的反潜编成逻辑。

索敌约束：无论索敌是否成功，阵型都不改变（保持 CombatPlan 中的 formation_when_spot_enemy_fails / formation_rules 为空）。

1. 小关快照与状态管理
1.1 状态快照 (DecisiveState)
维护一个 stage_enter_snapshot（进入当前小关时的状态快照）。

撤退刷新（Reset）：点“撤退”并确认后，将点数、舰船及强化等级（ship_levels: dict[str,int]）、副官、副官等级、技能已用记录全部恢复到快照状态。

血量例外：血量状态由游戏引擎负责，代码不回退、不记录。

技能状态回退：紫貂技能已用状态随小关重置（如 6-2 撤退，重新升到 Lv.8 会再次触发）。

1.2 需要新增/修改的字段
# DecisiveState 新增
instructor: str                  # 当前副官
instructor_level: int            # 章节级单值，跨小关继承，撤退回退

2. 购买逻辑与编队流程 (Buy & Fleet)
2.1 买船策略（战备舰队获取）
绝对优先级：考文垂（仅 6-1 A 点且未持有时买） > U-47 > U-1206 > 其他潜艇。

交互时序：扫描卡面识别 → 算余额 → 点选目标（卡框变亮） → 点黄色“确定” → 界面消失回到地图。点数不够时卡面会实时变灰，代码需自行拦截。

刷新限制：无目标点“刷新”（限一次）。

6-1 A 无目标：点最左侧第一张卡 + 确定（买完进图撤退重刷）。

6-2 A 无目标：点红色“关闭”退出购买页，然后撤退重刷。

2.2 动态出击与大破修理状态机（核心提速）
满 6 艘潜艇后，不再每次主动点“编队”，利用游戏弹窗和短条驱动修理。

未满 6 艘潜艇时（需手动上阵）：

流程：买完船回地图 → 点“编队” → 上阵 → 点“快速修理”页签 → 点“全部修理”大按钮 → 点“开始出征”。

已满 6 艘潜艇时（免编队快捷流程）：

流程：买完船/进图回地图 → 直接点“出征”。

情况 A：正常切入战斗（直接跳到 0.1 第 3 点的结算跳过逻辑）。

情况 B（非旗舰大破）：弹确认框 → 点“取消” → 点“编队” → 快速修理/全部修理 → 出征。

情况 C（旗舰大破）：中央出短条（1-2秒消失） → 代码等待2秒发现仍在图 → 点“编队” → 快速修理/全部修理 → 出征。

E6-3 J 点特殊流程：

打完 I 点选 J → 处理完买船界面回地图。

使用奇尔沙治技能（不进入战斗效果一直在）。

点“编队” → 快速修理 → 全部修理 → 点“开始出征”。

3. 副官切换与技能释放
3.1 副官切换 (SIFT 立绘匹配)
时机：仅在章节总览页进小关前。E6-1/2 紫貂，E6-3 奇尔沙治。

ROI 位置：x: 0.02~0.33, y: 0.13~0.86（避开标题与底栏）。

推荐组合流程：

截图立绘 ROI → 模板匹配 → current_instructor。
若匹配目标 → 直接进图（0 点击）。
若不匹配 → 点立绘开弹窗 → 在列表定位目标 → 按文字「替换」点击；若显示「工作中」则关闭。
切换后截图复核，仍不匹配则告警暂停。
3.2 技能释放与买经验
紫貂：每个战斗节点前 OCR 一次等级。

Lv >= 3 且未用 → 点技能 → 立刻连点买经验（余额 >=5 且未满级） → 标记已用 → 进图。

Lv >= 8 且未用 → 同上。

奇尔沙治：见 2.2-3（J 点前修完船再出征）。

买经验循环：

唯一终止条件：自算余额 score < 5 或 按钮变灰（满级）。

每次点击后重新读右上角余额（防 OCR 漂移），检测到“点数不足”弹窗则关闭并中止。

4. 旧代码改造清单 (基于 R1-R22 评估)
4.1 必须废弃/重写的逻辑
❌ 废弃战果采集：删除 collect_result_info 及评级判定，战斗结束直接连点回地图。

❌ 废弃反潜阵型判定：删除 get_formation 对 enemy_spec.yaml 的依赖，改认 is_key_point()。

❌ 废弃主动血量判断：删除 should_repair 等逻辑，改为出征 UI 弹窗响应。

❌ 废弃节点查表改造计划：保留 chr(ord(node)+1) 的字母硬加（因路线固定）。

4.2 需重构的核心点
R2 / R7 / R10：重写 choose_ships，注入潜艇优先级（考文垂>U47>U1206>其他）和拒绝凑数留空的规则。

R5 / R8：get_best_fleet 支持 6-1 A点只上考文垂，C点下掉，并加入 min_ships 判定（防止1艘船被自动判撤退）。

R12：state.ships 由 set 改为 dict，支持同名强化（+1/+2）计数。

R13 / R14 / R15：接入“余额循环买经验”、“OCR 读技能等级”、“灰按钮满级判定”。

R16 / R21：引入立绘 SIFT 匹配，实现总览页副官切换。

5. 给 DSH 的核心开发约束
严禁在战斗结算页写死 sleep：检测到战斗结束（或直接无脑连点屏幕），直到识别到地图页 UI（编队/出征按钮）即可。

UI 轮询代替硬编码 sleep：点击出征后，必须用条件轮询（等待战斗画面特征，或发现大破短条）卡时间。

纯逻辑必须带断言：对于买船优先级、快照恢复、夜战阵型判定、经验购买循环，必须编写可执行单测。

配置分离：潜艇名单、关键点阵型、技能触发等级等，必须写进 DecisiveConfig，严禁在 logic.py 写 if node == 'A' 硬编码。
