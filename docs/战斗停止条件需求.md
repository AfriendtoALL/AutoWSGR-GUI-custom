# 战斗停止条件需求

增加一项战斗停止条件：**指定槽位的舰船到达目标等级即停止后续战斗**。

## 需求定义

用户在出征规划中可配置：
- **监控槽位**：旗舰 / 1 号位 / … / 5 号位
- **目标等级**：整数

每轮战斗结束后，若监控槽位的舰船等级 ≥ 目标等级，则本轮结束后不再发起下一轮。

## 已确认的决策

### 1. 监控维度：槽位，不是舰名

第一版按**槽位**监控，不按舰名。

理由：练级场景通常就是“练旗舰”或“练某个固定位置”，槽位足够表达；舰名会引入同名舰、改修改名等边界，留作后续增强。

### 2. 目标数量：单槽位单目标

第一版只支持**一个槽位 + 一个目标等级**。

多槽位、多目标（任一 / 全部）留作后续增强，不在第一版范围。

### 3. 停止时机：打完本轮再停，不做立刻撤退

等级命中后，**当前轮次战斗照常打完**，只是不再发起下一轮。

不做“结算后立刻撤退”：那需要动战斗状态机（`RESULT → 撤退`），不在本需求范围内。

## 已知边界

### 时机滞后一轮

等级识别只发生在**出征准备页**（`_recognize_fleet_levels` → `FleetInfo.ship_levels` → `Ship.level`），战果结算页和经验结算页都没有等级 OCR。

因此：本轮打完升的级，要到**下一轮准备页**才可见。**“刚好升到目标等级”的那一轮会多打一轮**。UI 上必须明确提示这一点，避免用户误以为“到了就立刻停”。

### 适用范围

- ✅ 支持：常规战（normal_fight）、活动战（event_fight，继承 NormalFightRunner）、战役（campaign）
- ❌ 不支持：决战（`fleet` 在 `DecisiveState` 里，不在 `CombatResult` 上）、演习（无 `CombatResult.fleet`）

这两个路由需要在配置 UI 上显式禁用或隐藏该条件，避免用户配置后不生效。

## 实现路线：B 路线（前端求值）→ 5.11 迁移到后端

最初选择 **B 路线**：沿用现有战利品/掉落停止条件的前端求值架构，与它们完全同构。

理由：
- 后端 `run_rounds()` 尚不存在（5.11 待修），A 路线需要在四条路由里各写一遍谓词，等 5.11 收敛时再删掉重写，浪费；
- B 路线不依赖 5.11 排期，可立即开工；
- 与现有停止条件同构，用户不需要学习新概念，风险低。

> **2026-10-29 已迁移（5.11）**：`run_rounds()` 落地后，等级条件由后端按
> `fleet_levels` 求值，命中返回 `stop_reason='stop_condition'`；前端
> `StopConditionChecker` 只保留战利品/掉落逻辑，`handleTaskFinished`
> 只读后端 `stop_reason`。下面的 B 路线改动面作为历史记录保留。

### 改动面

**后端（1 个文件，1 个字段）**

1. `server/serializers.py`：`convert_combat_result` 补 `fleet_levels` 字段（槽位索引 → 等级）。当前 API 边界把 `fleet` 丢掉了，必须补，否则前端拿不到等级数据。

**前端（4 处）**

2. `StopConditionChecker`：增加 `level_ge` 分支，数据源为 `fleet_levels`。
3. `stop_condition` 校验白名单：增加 `level_slot` / `level_ge` 两项（对应现有的 `loot_count_ge` / `ship_count_ge`）。
4. 表单：增加“监控位置”下拉框 + “目标等级”输入框，复用 `bindStopConditionControl` / `renderStopConditionControl` 的结构。
5. `handleTaskFinished` 或 follow-up 逻辑：命中后不再塞下一轮。

### 不做的事

- 不改 `detect_ship_stats`（它是每节点一次的像素采样，只有血量，语义上不该拿来判等级）；
- 不改 `run_rounds()`（尚不存在，属于 5.11 的范围）；
- 不新增 OCR（`CombatResult.fleet` 已带 `Ship.level`，零新增 OCR）；
- 不做“立刻撤退”（需要动战斗状态机，不在范围内）；
- 不做多槽位 / 多目标（留作后续增强）。

## 验收标准

1. 构造一个 `fleet_levels = {0: 80, 1: 75, ...}` 的结果，`level_slot=0, level_ge=80` 时 checker 命中并触发停止；
2. 同上，`level_ge=81` 时不命中；
3. `level_slot=1, level_ge=75` 时命中（验证槽位索引正确）；
4. YAML 落盘后重新读入，`stop_condition` 中的 `level_slot` / `level_ge` 正确保留；
5. 命中后前端不再 follow-up 下一轮（检查 `handleTaskFinished` 分支）；
6. 演习 / 决战路由下配置该条件时不生效，UI 上有明确提示或禁用。
